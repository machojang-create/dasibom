# 시니어 정보 블로그 원고 쓰기

읽는 사람은 **은퇴 이후 세대 본인**입니다. 자녀가 아닙니다.
검색해서 들어와 찾던 것을 얻고 나가면 그것으로 충분합니다.

## 먼저 읽을 것

원고를 쓰기 전에 반드시 확인합니다.

- `blog/config.json` — 카테고리별 목차 템플릿, 문체 규칙, 금지 사항, 이미지 최소 장수
- `blog/README.md` 1~3장 — 이 블로그의 원칙과 사실 규칙
- `blog/out/B01_기초연금-수급자격-만-65세라면-먼저-확인할-것.json` — **기준이 되는 원고입니다. 톤이 헷갈리면 이걸 보세요.**

## 절대 어기지 않는 다섯 가지

### 1. 친절해야 합니다

읽는 분은 금융·세금·의료 전문가가 아닙니다. 아는 사람에게 쓰는 글이 아니라 **모르는 사람에게 쓰는 글**입니다.

- 어려운 말이 나오면 **그 자리에서 바로** 풉니다. 다음 문단으로 미루지 마세요.
  - 나쁜 예: `소득인정액이 기준 이하여야 합니다.`
  - 좋은 예: `소득인정액이 기준보다 낮아야 합니다. 쉽게 말씀드리면, 매달 버는 돈에다가 가지고 있는 재산을 돈으로 바꿔 더한 금액입니다.`
- 막히는 지점마다 **어디에 물어보면 되는지** 알려 줍니다.
  - `어렵게 생각하지 마십시오. 주민센터에 가셔서 "기초연금 신청하러 왔습니다" 한마디만 하시면 담당자가 하나씩 봐 드립니다.`
- 혼자 해결하지 않아도 된다고 말해 줍니다. 전화번호가 있으면 적습니다(1355, 1577-1000, 129 등).

### 2. 예시를 반드시 듭니다

**예시 없는 설명은 설명이 아닙니다.** 독자가 자기 경우에 대볼 수 있어야 합니다.

- 나쁜 예: `만 65세 이상이면 신청할 수 있습니다.`
- 좋은 예: `1961년 3월 15일에 태어나셨다면 2026년 3월 15일에 만 65세가 되십니다. 그러니 2026년 2월부터 신청하실 수 있습니다.`

숫자·날짜·조건이 나오는 자리에는 예시를 최소 하나 답니다. 나이 기준이면 생년월일 예시를 두세 개 들어 경우를 나눠 보여 주세요.

### 3. 감성적으로 씁니다

사무적인 안내문이 아니라 옆에서 알려주는 사람의 말투입니다.

- 서론은 **장면 하나**로 엽니다. `우편함에서 안내문을 꺼내 들고 한참 서 계셨던 적 없으신가요.`
- 마무리는 **오늘 할 수 있는 아주 작은 것 하나**로 닫습니다. `오늘 달력을 펴서 생일 앞 달에 동그라미 하나만 쳐 두십시오.`
- 한 문단이 세 줄을 넘으면 나눕니다. 눈으로 훑을 때 숨 쉴 자리가 있어야 합니다.
- 독자에게 **직접** 말합니다. `어르신은`, `부모님께` 같은 3인칭은 금지입니다.
- `~해드리세요`, `챙겨드리세요` 같은 돌봄 대상 취급도 금지입니다.

### 4. 분량은 2,600~3,400자

짧으면 다른 데서도 보는 흔한 정보가 됩니다. 늘리는 방법은 문장을 늘이는 것이 아니라 **예시와 경우의 수를 더하는 것**입니다.

내용이 많으면 4,000자까지 가도 됩니다. 억지로 줄이지 마세요.

### 5. 이미지는 최소 5장, 필요하면 더

대표 이미지 1장 + 본문 4장 이상. **내용에 따라 10장이 필요하면 10장 넣습니다.** 상한은 없습니다.

본문 이미지는 두 종류입니다. 원고 JSON 에 자리를 적어 두면 발행기가 그 자리에 넣습니다.

- `illustrations[]` — Gemini 로 만드는 그림. `{ after, prompt }`
- `figures[]` — 본문 내용을 옮긴 정보 카드. `{ type, after, title, items }`

`after` 에는 **본문에 실제로 있는 줄을 글자 그대로** 옮겨 적습니다. 안 맞으면 검수기가 막습니다.

카드 종류는 다섯 가지입니다.

| type | 쓰는 곳 |
|---|---|
| `checklist` | 준비물, 서류, 증상 확인 — 한 줄에 하나 |
| `steps` | 순서가 있는 것 |
| `compare` | 되는 것 / 안 되는 것 (`left`, `right` 에 `label`, `items`) |
| `note` | 하면 안 되는 것, 놓치면 손해 보는 것 |
| `summary` | 세 줄 요약 |

일러스트 프롬프트는 **장면**으로 씁니다. 인물의 나이대, 장소, 하는 동작, 분위기. 글자·숫자·상표가 들어가는 장면은 안 됩니다.

## 쓰면 안 되는 것

`blog/config.json` 의 `writing.volatility_rules` 가 원본입니다. 요약하면,

| 써도 되는 것 | 쓰면 안 되는 것 |
|---|---|
| 나이 기준 (만 65세), 자격 요건 | **금액·요율·지원금 액수** |
| 생년월일 예시 (1961년 3월생) | **올해·작년·요즘** 같은 상대적 시간 표현 |
| 계산하는 방법, 무엇에 따라 갈리는지 | 출처 없는 통계·비율·순위 |
| 확인처 (주민센터·공단·복지로) | 최고·유일·100%·무조건 같은 단정 |

**금액을 적지 않는 이유**는 자동 발행이기 때문입니다. 액수는 매년 1월에 바뀌고, 한 번 적으면 연초마다 과거 글 전체가 틀린 글이 됩니다. 대신 **무엇에 따라 갈리는지와 확인처**를 줍니다.

그 밖에:
- 본문에 마크다운 기호(`**`, `#`, `-`)를 쓰지 않습니다. 네이버 에디터에 그대로 찍힙니다.
- 본문에 링크 주소를 쓰지 않습니다.
- 특정 병원·제품·상표를 권하지 않습니다. 성분 이름, 고르는 기준으로만.
- 의학적 단정(낫는다)을 하지 않습니다. 건강 글은 **"병원에 가야 할 때"** 항목을 반드시 넣습니다.
- **다시봄라이프를 본문에 쓰지 않습니다.** `자서전과 기록` 카테고리만 예외이고 그때도 글 전체에서 한 번뿐입니다.

## 글 끝에 직접 쓰지 말 것

두 가지는 발행기가 자동으로 붙입니다. 본문에 또 쓰면 두 번 나옵니다.

1. 해마다 다시 확인하시라는 안내 (`config.json` 의 `writing.annual_notice`)
2. 운영 주체 카드 (`config.json` 의 `footer_card`)

## 작업 순서

```bash
cd blog

# 1. 어떤 주제가 남았는지
npm run status
npm run cats

# 2. 원고를 씁니다 — out/<ID>_<제목>.json 에 직접 작성
#    (형식은 out/B01_*.json 을 그대로 따라가세요)

# 3. 검수. 차단이 하나라도 있으면 고칩니다
node lint_post.mjs --post out/B01_xxx.json

# 4. 이미지
node gen_image.mjs   --post out/B01_xxx.json   # 대표
node gen_figures.mjs --post out/B01_xxx.json   # 정보 카드
node gen_illust.mjs  --post out/B01_xxx.json   # 일러스트 (Gemini)

# 5. 눈으로 확인
node preview_post.mjs --post out/B01_xxx.json
```

원고 JSON 의 필수 항목: `id`, `category`, `category_name`, `naver_category`, `keyword`, `title`, `body`, `summary`, `tags`, `cta`(항상 `null`), `illustrations`, `figures`.

제목은 32자 이내, 이모지 없이, **검색 키워드가 앞쪽에** 오게 합니다.
태그는 5~7개, 해시 없이 단어만.

## 쓰고 나서 스스로 물어볼 것

- 이 글에 **예시가 몇 개** 들어갔나. 하나도 없으면 다시 쓴다.
- 어려운 말을 그 자리에서 풀었나. 넘어간 곳이 있으면 되돌아간다.
- **어디에 물어보라고 알려 줬나.** 전화번호나 창구 이름이 한 번도 안 나왔으면 넣는다.
- 이미지가 다섯 장이 되나. 단계가 많은 글인데 다섯 장뿐이면 더 넣는다.
- 다른 블로그에도 그대로 있을 법한 문장만 있지 않나. 그렇다면 아직 안 끝난 것이다.
