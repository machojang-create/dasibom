# 다시봄라이프 블로그 운영

**시니어 정보 블로그**입니다. 네이버 블로그(blog.naver.com/dasibomlife)에 글을 쓰고 발행하는 파이프라인이 들어 있습니다.

---

## 1. 이 블로그의 원칙

**정보 블로그입니다. 다시봄라이프 홍보 블로그가 아닙니다.**

은퇴 이후 세대가 검색해서 찾아오면, 찾던 정보를 주고 끝냅니다. 읽고 나서 "쓸모 있었다"로 끝나면 그것으로 충분합니다.

- **본문에 다시봄라이프가 나오지 않습니다.** 글 생성기는 링크의 존재 자체를 모릅니다
- **글마다 다른 CTA 를 고민하지 않습니다.** 모든 글 끝에 똑같은 카드 하나가 붙습니다. 발행기가 붙입니다
- **사이드바에 배너 하나**를 답니다. 그게 전부입니다

```
─────────────
이 블로그는 다시봄라이프가 씁니다.
은퇴 이후의 하루를 위한 서비스 — dasibomlife.com
```

카드 문구는 `config.json` 의 `footer_card` 에 있습니다. `enabled: false` 로 두면 카드 없이 정보만 발행됩니다.

**왜 이렇게 하나.** 글 내용에 맞춰 링크를 고르기 시작하면 글이 그 링크를 향해 휘어집니다. 국민연금 글 끝에 일자리 링크를 붙이는 식이 됩니다. 그러면 독자가 광고로 읽고, 네이버는 상업성 블로그로 판정합니다. 저품질을 맞으면 검색 노출 자체가 사라집니다.

## 2. 카테고리 3개

| 카테고리 | 비중 | 무엇을 쓰나 |
|---|---|---|
| **돈과 혜택** | 40% | 기초연금·국민연금·교통카드·경로우대·의료 혜택·세금 감면 · 주택연금·퇴직금·건강보험료·상속 |
| **건강과 영양** | 35% | 영양소별 설명(부족하면 생기는 일 / 어떤 음식에 많은지) · 집에서 하는 스트레칭 |
| **취미와 반려동물** | 25% | 시니어 취미 추천과 분석 · 강아지·고양이·화분·텃밭·어항 |

**정책과 금융을 나누지 않았습니다.** 국민연금 조기수령이 정책인지 금융인지, 은퇴 후 건강보험료가 어느 쪽인지 — 쓰는 사람은 구분해도 **읽는 사람은 구분하지 않습니다.** 받는 것과 가진 것을 한자리에 둡니다.

카테고리 셋이면 사이드바에서 한눈에 들어옵니다. 늘리고 싶으면 글이 쌓여 하나가 40편을 넘길 때 쪼개는 게 순서입니다.

```bash
npm run cats     # 카테고리별로 무슨 글이 들어가는지, 어떻게 쓰는지
```

**돈과 혜택이 검색 유입이 가장 큽니다.** 기초연금·교통카드처럼 검색 의도가 명확한 주제라 상단만 잡으면 꾸준히 들어옵니다.

### 카테고리마다 쓰는 법이 다릅니다

`config.json` 의 `categories[].guide` 에 있고, 글 생성기가 매번 프롬프트에 넣습니다.

- **돈과 혜택** — 법률 용어를 반드시 풀어서. 자격 조건은 나이/소득/재산으로 갈래를 나눠서. 준비물은 체크리스트로. 금융상품은 추천·비교하지 않음
- **건강과 영양** — ①몸에서 하는 일 ②부족하면 나타나는 신호 ③어떤 음식에 많은지 ④주의할 점 순서. 질병이 낫는다고 쓰지 않음
- **취미와 반려동물** — "해보세요"로 끝내지 않음. 시작에 필요한 것과 걸림돌을 구체적으로

## 3. 문체와 사실 규칙

### 독자를 대하는 법

읽는 사람은 **시니어 본인**입니다. 자녀에게 설명하듯 쓰면 읽는 사람이 대상화됩니다.

- 독자에게 **직접** 말합니다. `어르신은`, `부모님께` 같은 3인칭 금지
- `~해드리세요`, `챙겨드리세요` 같은 돌봄 대상 취급 금지
- 외래어·줄임말 금지. 꼭 쓰면 우리말 풀이를 붙일 것
- 나이를 이유로 못 한다가 아니라, 방법을 바꾸는 이야기로
- 어떤 서비스나 앱도 권하지 않음

### 시간이 지나도 틀리지 않게

`config.json` 의 `writing.volatility_rules` 에 있습니다.

| 써도 되는 것 | 쓰면 안 되는 것 |
|---|---|
| 나이 기준 (만 65세 등) | 금액·요율·지원금 액수 |
| 자격 요건의 갈래 | 수익률·연금 수령액 |
| 계산하는 방법 | 지어낸 통계·비율·순위 |
| 확인처 (주민센터·공단·복지로) | 상대적 시간 표현 (올해·작년·요즘) |

**나이와 자격 요건은 적어도 됩니다.** 잘 바뀌지 않고, 이게 없으면 정책 글이 쓸모없어집니다. 반면 금액은 해마다 바뀌므로 "주민센터에서 확인" 으로 넘깁니다.

### 검수기가 막습니다

프롬프트로 넣는 것만으로는 부족합니다. `lint_post.mjs` 가 발행 직전에 검사하고, **차단 항목이 하나라도 있으면 발행을 멈춥니다.**

```bash
npm run lint                            # out/ 의 모든 원고
node lint_post.mjs --post out/B01_x.json
```

| 차단 (발행 중단) | 확인 권장 |
|---|---|
| **본문에 서비스 이름** (다시봄·봄이) | 제목 32자 초과 |
| **다른 데로 넘기려는 마무리** | 제목에 검색 키워드 없음 |
| 독자를 3인칭으로 부름 | 태그 개수 (5~12개 밖) |
| 돌봄 대상 취급 | 나이를 한계로 서술 |
| 금액·가격 / 연금·요율 수치 | 제품·병원 추천 가능성 |
| 금융상품 추천·판단 | 분량 범위 밖 |
| 상대적 시간 표현 | |
| 출처 없는 통계·비율 / 순위 | |
| 단정 표현 (최고·유일·100%) | |
| 의학적 단정 | |
| 마크다운 기호 잔존 / 본문 속 링크 | |
| 분량 목표의 80% 미만 / 제목 이모지 | |

통계는 **같은 문장에 출처가 있으면 통과**시킵니다. "조사에 따르면 68%" 는 지나가고, 근거 없는 "100%" 만 걸립니다.

규칙이 과하면 `lint_post.mjs` 의 `RULES` 를 조정하거나 `--skip-lint` 로 넘길 수 있습니다. 다만 **넘기기 전에 왜 걸렸는지는 꼭 보세요.**

## 4. 블로그 기본 세팅 (최초 1회)

스킨·카테고리·프로필은 네이버에 API 가 없어서 관리 화면에서 손으로 해야 합니다.
**순서와 체크리스트는 [SETUP_NAVER.md](SETUP_NAVER.md) 를 보세요.**

```bash
node gen_blog_assets.mjs
# out/assets/ → title.png / profile.png / side_banner.png / mobile_cover.png
```

색과 로고는 앱에서 그대로 가져옵니다 — `#0e9d7d`(manifest 의 theme_color), logo.svg 의 해·새싹.

놓치기 쉬운 두 가지만 미리 말씀드립니다.

1. **검색엔진 수집 허용** — 이게 꺼져 있으면 나머지가 전부 무의미합니다.
2. **카테고리 이름을 글자 하나 안 틀리게** — `config.json` 의 `naver.category_map` 과 다르면 발행 시 카테고리 선택이 실패합니다.

## 5. 설치 (최초 1회, 대표님 PC에서)

```bash
cd blog
npm install
npx playwright install chromium

cp .env.example .env       # ANTHROPIC_API_KEY 를 채웁니다
npm run login              # 브라우저에서 직접 네이버 로그인
```

한글 폰트가 필요합니다 (썸네일 글자가 네모로 나오면 이것 때문입니다).

```bash
fc-list :lang=ko family                          # 설치된 한글 폰트 확인
sudo apt install fonts-nanum && fc-cache -fv     # Ubuntu/WSL

# macOS / Windows 는 config.json 의 brand.font_family 를 바꾸세요
#   macOS → "AppleSDGothicNeo"  /  Windows → "Malgun Gothic"
```

`.naver_session.json` 은 **로그인 상태 그 자체입니다.** `.gitignore` 에 넣어두었으니 절대 커밋하지 마세요. 만료되면 `npm run login` 을 다시 돌리면 됩니다.

## 6. 매일 쓰는 명령

```bash
npm run status      # 큐 현황 (카테고리별 남은 편수, 몇 주치인지)
npm run cats        # 카테고리별로 무슨 글이 들어가는지
npm run draft       # 원고 + 이미지만 생성. 발행 안 함
npm run post        # 원고 → 이미지 → 검수 → 다음 발행 슬롯에 예약
npm run post:now    # 예약 대신 즉시 발행
npm run expand      # 소진 임박한 카테고리에 새 주제 자동 보충
npm run lint        # out/ 의 원고 검수
```

세부 옵션:

```bash
node run.mjs --count 3               # 3편 연속 (예약 슬롯이 차례로 밀림)
node run.mjs --id B01                # 특정 주제 지정
node run.mjs --category money       # 카테고리 지정
node run.mjs --headed                # 브라우저 보면서 (문제 생겼을 때)
```

**처음 2~3주는 `npm run draft` 로 원고를 눈으로 확인한 뒤 발행하시길 권합니다.**

발행 주기 기본값은 **주 3회, 월·수·금 오전 9시**입니다 (`config.json` 의 `schedule`). 현재 큐는 70편으로 약 23주치입니다.

## 7. 자동 실행 (선택)

큐에 주제가 충분히 쌓인 뒤에 거는 걸 권합니다.

```
# macOS / Linux — crontab
0 8 * * 1,3,5 cd /경로/dasibom/blog && /usr/local/bin/node run.mjs --now >> out/cron.log 2>&1
```

Windows 는 작업 스케줄러에 프로그램 `node`, 인수 `run.mjs --now`, 시작 위치를 `blog` 폴더로.

자동 실행은 세션 만료에 취약합니다. 로그(`out/cron.log`)를 주 1회는 확인하세요.

## 9. 발행이 깨졌을 때

네이버는 예고 없이 에디터 DOM 을 바꿉니다. 발행 실패는 대부분 이것입니다.

실패하면 **어느 단계에서 멈췄는지** 로그에 찍히고 `out/error_*.png` 스크린샷이 남습니다.

```bash
node publish_naver.mjs --post out/B01_xxx.json --headed --pause   # 셀렉터 확인
node publish_naver.mjs --post out/B01_xxx.json --dry-run --headed # 발행 없이 화면만
```

Playwright Inspector 의 Explore 로 바뀐 셀렉터를 찍어서 `lib/selectors.mjs` 의 해당 항목 **맨 앞에** 추가하세요. 기존 값은 지우지 마세요 — 네이버가 되돌릴 때가 있습니다.

## 10. 큐가 마르지 않게

`npm run status` 가 카테고리별로 몇 주치 남았는지 보여줍니다. 8주 미만이면 `주의`, 4주 미만이면 `보충 필요`.

```bash
npm run expand                                      # 8주 미만인 카테고리를 알아서 채움
node expand_queue.mjs --category money --count 15
node expand_queue.mjs --auto --threshold 12         # 임계값을 올려 미리 채움
```

**중복은 큐 전체 기준으로 걸립니다.** 발행이 끝난 글까지 포함해 제목과 키워드를 프롬프트에 넣기 때문에, 오래 운영해도 같은 주제가 다시 나오지 않습니다.

**추가된 주제는 `angle` 을 훑어보세요.** 각도가 뻔하면 글도 뻔해집니다.

## 11. 아직 안 한 것

- **애드포스트** — 글이 쌓이고 유입이 잡힌 뒤에 판단할 문제입니다.
- **네이버 서치어드바이저** — 유입 키워드를 봐야 카테고리 비중을 재조정할 수 있습니다. 글이 20~30편 쌓인 뒤에 등록하세요.
