# 다시봄라이프 블로그 운영

네이버 블로그(blog.naver.com/dasibomlife) 글 작성부터 발행까지 자동화한 파이프라인입니다.

---

## 1. 왜 블로그인가

다시봄라이프 웹앱은 PWA(SPA)라서 검색엔진이 내용을 거의 못 읽습니다. 앱 안의 콘텐츠는 로그인·진입 후에야 나오니 검색 유입이 잡히지 않습니다. 블로그가 그 결핍을 메우는 **검색 진입로**입니다.

**방향은 블로그 → 앱 한 방향입니다.** 앱 안에서 블로그로 내보내면 이탈만 만듭니다.

| | 웹앱 | 블로그 |
|---|---|---|
| 읽는 사람 | 이미 쓰는 사람 | 아직 다시봄을 모르는 사람 |
| 글의 성격 | 오늘의 콘텐츠, 서비스 기능 | 검색해서 들어오는 글 |
| 독자 | 시니어 본인 | **시니어 본인** (+ B2G 담당자) |
| 목적 | 계속 쓰게 하기 | 검색으로 만나고 신뢰 쌓기 |

앱 콘텐츠를 블로그에 그대로 복사하면 안 됩니다. 검색엔진이 중복으로 보고 양쪽 다 순위를 낮춥니다. **소재만 재활용하고 글은 다시 씁니다.**

---

## 2. 독자와 카테고리

### 독자는 시니어 본인입니다

앱 온보딩 기본값이 1960년생이고, 일자리·건강·취미·오락이 전부 본인용 기능입니다. **구독료 4,900원은 본인이 결제하는 금액입니다.** 커피 한 잔 값을 자녀에게 부탁하는 것보다 본인이 카드를 꽂는 편이 간단합니다. 지금 60대는 간편결제를 씁니다.

자녀가 개입해야 하는 계층은 따로 있습니다. `carekiosk.html` 이 받는 **장기요양인정번호(L번호)** 대상자 — 요양등급·거동 불편 계층이고, 그쪽은 **B2G 가 커버합니다.** 자녀 결제는 그 사이의 좁은 틈이지 사업의 축이 아닙니다.

| | B2C 구독 | B2G 돌봄 |
|---|---|---|
| 대상 | 60대 중반. 일자리·건강·취미를 찾는 층 | 장기요양 등급자 |
| 접점 | 본인 스마트폰 | 복지관 태블릿 |
| 비용 | **본인** | 지자체 |

### 카테고리 7개와 비중

**이름만 보고 무슨 글인지 알 수 있어야 합니다.** 방문자는 사이드바에서 3초 안에 볼지 말지 정합니다. 감성적인 이름은 클릭을 못 만듭니다.

| 카테고리 | 비중 | 무엇이 들어가나 |
|---|---|---|
| 연금과 노후 준비 | 18% | 국민연금·기초연금·주택연금·퇴직금·건강보험료·상속과 증여 |
| 건강한 노후 | 20% | 치매 예방·기억력·낙상·약 복용·불면·무릎·식사 |
| 취미와 반려생활 | 15% | 강아지·고양이·화분·텃밭·어항·서예·등산·노래교실 |
| 돌봄 정책과 현장 | 15% | 고독사 예방·스마트 경로당·안부확인·장기요양 기록 |
| 일자리와 재취업 | 12% | 재취업·경력 전환·이력서·면접·노인일자리 |
| 자서전과 기록 | 12% | 자서전 쓰는 법·손주에게 남길 글·마음의 유언·말동무·인터뷰 |
| 추억과 놀거리 | 8% | 옛날 오락실·화투·옛 물건·꿈 해몽·요즘 말 |

언제든 확인할 수 있습니다.

```bash
npm run cats     # 카테고리별 내용·독자·CTA·주제 목록
```

**비중 5% 이하 카테고리는 만들지 마세요.** 클릭했을 때 글이 두세 편뿐이면 블로그 전체가 부실해 보입니다.

### 이건 광고 블로그가 아닙니다

**기본은 CTA 없음입니다.** 68편 중 25편에만 링크가 붙고, B2G(8편)를 빼면 60편 중 17편입니다. 나머지는 정보로 시작해서 정보로 끝냅니다. 그런 글에는 `다시봄`·`봄이` 를 한 번도 쓰지 않습니다.

CTA 는 **글의 결론이 앱 기능으로 정말로 이어질 때만** 붙입니다. 처음엔 68편 전부에 링크를 박아뒀는데, 이런 것들이었습니다.

| 글 | 붙였던 CTA | 판정 |
|---|---|---|
| 국민연금 수령 시기 | 시니어 일자리 | 억지 — 걷어냄 |
| 이 나이에 강아지를 키워도 될까 | 수다쟁이 화분 | 억지 — 걷어냄 |
| 노래교실이 인기 있는 이유 | 시니어 토론장 | 억지 — 걷어냄 |
| 말할 사람이 없어 입을 안 뗄 때 | 구독 | 취약한 상황에 판매 — 걷어냄 |
| 옛날 오락실 게임 | 추억의 오락실 | 자연스러움 — 유지 |
| 자서전 어디서부터 시작할까 | 자서전 | 자연스러움 — 유지 |

이유는 둘입니다.

1. **억지 CTA 는 신뢰를 깎습니다.** 연금 정보를 찾아 들어왔는데 일자리 링크가 붙어 있으면 광고로 읽힙니다.
2. **네이버가 상업성으로 판정합니다.** 모든 글이 자사 링크로 끝나는 신규 블로그는 저품질을 맞습니다. 저품질이면 검색 노출 자체가 사라집니다. 검색 진입로를 만들려다 진입로를 막는 셈입니다.

**운영 주체를 숨기는 것은 아닙니다.** 블로그 프로필과 소개글에 다시봄라이프임을 밝힙니다. 글마다 광고를 붙이지 않을 뿐입니다.

CTA 가 있는 글에서도 브랜드는 마지막 한 번뿐입니다. 세 번 이상 나오면 검수기가 막습니다.

### 카테고리별 CTA 비율

```bash
npm run cats     # 카테고리별 CTA 몇 편인지 함께 나옵니다
```

| 카테고리 | CTA | 왜 |
|---|---|---|
| 연금과 노후 준비 | 0/12 | 앱에 금융 기능이 없습니다. 억지로 붙이지 않습니다 |
| 건강한 노후 | 2/10 | 약 복용·마음 상태 글만 |
| 취미와 반려생활 | 4/15 | 식물·어항 글만. 강아지·고양이·서예·등산은 정보로 |
| 돌봄 정책과 현장 | 8/8 | B2G. 도입 검토가 목적이라 문의처가 없으면 불친절합니다 |
| 일자리와 재취업 | 3/5 | 실제로 일자리를 찾는 기능이 있습니다 |
| 자서전과 기록 | 5/13 | 직접 써보는 것으로 이어지는 글만 |
| 추억과 놀거리 | 3/5 | 오락실·화투·꿈풀이. 앱 콘텐츠와 1:1 |

### 주제별 CTA 지정

**주제에 `cta_key` 가 있으면 CTA 를 붙이고, 없으면 붙이지 않습니다.** 값은 `config.json` 의 `app_map` 키입니다.

```json
{ "id": "P11", "category": "hobby_pet", "cta_key": "guppy" }   ← CTA 있음
{ "id": "P01", "category": "hobby_pet" }                        ← 정보로 끝
```

예외는 `돌봄 정책과 현장` 하나입니다. 카테고리에 `cta_default: true` 가 있어서 `cta_key` 를 안 적어도 문의처가 붙습니다. B2G 글은 도입 검토가 목적이라 문의처가 없으면 오히려 불친절합니다.

새 주제를 추가할 때 **`cta_key` 를 붙일지 말지는 한 번 더 생각하세요.** 기준은 하나입니다 — 글을 다 읽은 사람이 그 링크를 자연스럽게 누를 것 같은가. 아니면 붙이지 않습니다.

## 3. 문체와 변동성 규칙

### 독자를 대하는 법

`config.json` 의 `writing.reader_rules` 에 있고 시스템 프롬프트로 매번 들어갑니다.

- 독자에게 **직접** 말합니다. `어르신은`, `부모님께` 같은 3인칭 금지
- `~해드리세요`, `챙겨드리세요` 같은 돌봄 대상 취급 금지
- 외래어·줄임말 금지. 꼭 쓰면 우리말 풀이를 붙일 것
- 나이를 이유로 못 한다가 아니라, 방법을 바꾸는 이야기로

`돌봄 정책과 현장`(B2G)만 예외입니다. 그 글의 독자는 담당 실무자라 업무 문서 톤으로 씁니다. 검수기도 이 카테고리에는 위 규칙을 적용하지 않습니다.

### 변동성 규칙

AI가 쓴 글에서 가장 위험한 건 **시간이 지나면 틀리는 문장**과 **출처 없는 숫자**입니다. `config.json` 의 `writing.volatility_rules` 에 넣어두었고 시스템 프롬프트로 매번 들어갑니다.

- 상대적 시간 표현(올해, 작년, 요즘) 금지
- 통계·비율·순위를 지어내지 말 것
- 지원금 액수·신청 기간은 "주민센터에 확인" 으로 안내
- 가격·요금제를 본문에 쓰지 말 것
- 의학적 단정 금지, "전문의와 상의" 로 마무리
- 특정 병원·제품 추천 금지
- **금융상품(연금저축·펀드·보험)을 추천하거나 비교하지 말 것**
- **수익률·연금 수령액·보험료를 숫자로 적지 말 것.** 판단 기준과 확인처(국민연금공단·건강보험공단·주민센터)만
- 세무·법률 판단은 단정하지 말고 "세무사·법무사와 상의" 로 마무리

규칙을 바꾸려면 `config.json` 만 고치면 됩니다. 코드는 손댈 필요 없습니다.

### 규칙을 지켰는지 확인하는 장치

프롬프트로 넣는 것만으로는 부족합니다. 모델이 지켰는지는 별개고, 발행되고 나서 발견하면 늦습니다. `lint_post.mjs` 가 발행 직전에 원고를 검사하고, **차단 항목이 하나라도 있으면 발행을 멈춥니다.**

```bash
npm run lint                            # out/ 의 모든 원고
node lint_post.mjs --post out/M01_x.json
```

| 차단 (발행 중단) | 확인 권장 (발행은 됨) |
|---|---|
| **독자를 3인칭으로 부름** (어르신은·부모님께) | 제목 32자 초과 |
| **돌봄 대상 취급** (~해드리세요) | 제목에 검색 키워드 없음 |
| **CTA 없는 글에 브랜드 언급** | **무언가로 넘기려는 마무리** |
| **브랜드 3회 이상 반복** | 제품·병원 추천 가능성 |
| **금융상품 추천·판단** | **나이를 한계로 서술** |
| **연금·요율 수치** | |
| 상대적 시간 표현 (올해·작년·요즘) | |
| 출처 없는 통계·비율 | |
| 순위 표현 | |
| 금액·가격 | |
| 단정 표현 (최고·유일·100%) | |
| 의학적 단정 | |
| 금지 표현 (`config.json`) | |
| 마크다운 기호 잔존 | |
| 본문 속 링크 (CTA 중복) | |
| 분량 목표의 80% 미만 | |
| 제목 이모지 | |

통계는 **같은 문장에 출처가 있으면 통과**시킵니다. "조사에 따르면 68%" 는 지나가고, 근거 없는 "100%" 만 걸립니다.

**독자 관련 세 규칙은 카테고리를 봅니다.** `돌봄 정책과 현장`(실무자 대상)에는 적용하지 않습니다. 그 글의 독자는 시니어 본인이 아니기 때문입니다.

**CTA 가 없는 글에 `다시봄`·`봄이` 가 나오면 차단합니다.** 링크 없이 서비스 이름만 흘리는 게 더 광고처럼 읽힙니다.

규칙이 과하다고 판단되면 `lint_post.mjs` 의 `RULES` 를 조정하거나, 그 글만 `--skip-lint` 로 넘길 수 있습니다. 다만 **넘기기 전에 왜 걸렸는지는 꼭 보세요.** 대부분은 실제 문제입니다.

## 4. 블로그 기본 세팅 (최초 1회)

스킨·카테고리·프로필은 네이버에 API 가 없어서 관리 화면에서 손으로 해야 합니다.
**순서와 체크리스트는 [SETUP_NAVER.md](SETUP_NAVER.md) 를 보세요.**

디자인 자산은 명령 한 줄로 만듭니다.

```bash
node gen_blog_assets.mjs
# out/assets/ → title.png(966x300) / profile.png(400x400) / mobile_cover.png(1300x420)
```

색과 로고는 앱에서 그대로 가져옵니다 — `#0e9d7d`(manifest 의 theme_color), logo.svg 의 해·새싹. `config.json` 의 `brand` 에 모여 있고, 썸네일 생성기도 같은 값을 씁니다. **앱 로고나 색이 바뀌면 `config.json` 의 `brand` 와 `lib/brand.mjs` 를 같이 고치세요.** 따로 놀면 브랜드가 두 개가 됩니다.

세팅에서 놓치기 쉬운 두 가지만 미리 말씀드립니다.

1. **검색엔진 수집 허용** — 이게 꺼져 있으면 나머지가 전부 무의미합니다.
2. **카테고리 이름을 글자 하나 안 틀리게** — `config.json` 의 `naver.category_map` 과 다르면 발행 시 카테고리 선택이 실패합니다.

## 5. 설치 (최초 1회, 대표님 PC에서)

```bash
cd blog
npm install
npx playwright install chromium

cp .env.example .env
# .env 를 열어 ANTHROPIC_API_KEY 를 채웁니다
```

한글 폰트가 필요합니다 (썸네일 글자가 네모로 나오면 이것 때문입니다).

```bash
# 설치된 한글 폰트 확인
fc-list :lang=ko family

# Ubuntu/WSL
sudo apt install fonts-nanum && fc-cache -fv

# macOS / Windows 는 config.json 의 brand.font_family 를 바꾸세요
#   macOS   → "AppleSDGothicNeo"
#   Windows → "Malgun Gothic"
```

네이버 로그인 세션을 만듭니다.

```bash
npm run login
```

브라우저가 뜨면 **직접** 아이디/비밀번호를 넣고 로그인하세요. 네이버는 자동 입력을 차단하기 때문에 수동이 가장 안정적입니다. 2단계 인증도 이 창에서 통과하시면 됩니다. 로그인이 끝나면 터미널로 돌아와 Enter.

`.naver_session.json` 이 생깁니다. **이 파일은 로그인 상태 그 자체입니다.** `.gitignore` 에 넣어두었으니 절대 커밋하지 마세요. 세션이 만료되면 `npm run login` 을 다시 돌리면 됩니다.

## 6. 매일 쓰는 명령

```bash
npm run status      # 큐 현황 (카테고리별 남은 편수, 몇 주치인지, 보충 필요 여부)
npm run draft       # 원고 + 이미지만 생성. 발행 안 함
npm run post        # 원고 → 이미지 → 다음 발행 슬롯에 예약
npm run post:now    # 예약 대신 즉시 발행
npm run expand      # 소진 임박한 카테고리에 새 주제 자동 보충
npm run lint        # out/ 의 원고 검수
npm run cats        # 카테고리별로 무슨 글이 들어가는지
```

`post` / `post:now` 는 **발행 직전에 검수를 자동으로 돌립니다.** 차단 항목이 있으면 발행하지 않고 멈춥니다.

세부 옵션:

```bash
node run.mjs --count 3                 # 3편 연속 (예약 슬롯이 차례로 밀림)
node run.mjs --id W01                  # 특정 주제 지정
node run.mjs --category care_policy    # 카테고리 지정
node run.mjs --headed                  # 브라우저 보면서 (문제 생겼을 때)
```

**처음 2~3주는 `npm run draft` 로 원고를 눈으로 확인한 뒤 발행하시길 권합니다.** 문체와 변동성 규칙이 의도대로 나오는지 보고, `config.json` 의 `writing.tone` 을 다듬는 게 좋습니다.

발행 주기는 `config.json` 의 `schedule` 에 있습니다. 기본값은 **주 3회, 월·수·금 오전 9시**입니다. 혼자 운영하시는 상황이면 주 1~2회로 줄이는 걸 권합니다 — 주 3회로 두면 큐 소진이 그만큼 빨라집니다 (현재 65편, 주3회 기준 약 22주치). 소진 대책은 10번 항목을 보세요.

## 9. 발행이 깨졌을 때

네이버는 예고 없이 에디터 DOM 을 바꿉니다. 발행 실패는 코드 버그가 아니라 대부분 이것입니다.

실패하면 **어느 단계에서 멈췄는지** 로그에 찍히고 `out/error_*.png` 스크린샷이 남습니다.

```bash
node publish_naver.mjs --post out/M01_xxx.json --headed --pause
```

브라우저가 열린 채 멈춥니다. Playwright Inspector 의 Explore 로 바뀐 셀렉터를 찍어서 `lib/selectors.mjs` 의 해당 항목에 **맨 앞에** 추가하세요. 후보 배열이라 위에서부터 시도합니다. 기존 값은 지우지 말고 두세요 — 네이버가 되돌릴 때가 있습니다.

발행 없이 화면만 확인:

```bash
node publish_naver.mjs --post out/M01_xxx.json --dry-run --headed
```

## 10. 큐가 마르지 않게 하기

`npm run status` 가 카테고리별로 **몇 주치 남았는지** 계산해서 보여줍니다. 전체 편수가 아니라 그 카테고리의 목표 비중만큼 소비된다고 보고 나눈 값입니다.

- 8주 미만 → `주의`
- 4주 미만 → `보충 필요`

보충은 자동으로 됩니다.

```bash
npm run expand                                    # 8주 미만인 카테고리를 알아서 채움
node expand_queue.mjs --category hobby_pet --count 15
node expand_queue.mjs --auto --threshold 12       # 임계값을 12주로 올려 미리 채움
node expand_queue.mjs --category care_policy --count 8 --dry-run
```

**중복은 큐 전체를 기준으로 걸러집니다.** 발행이 끝난 글까지 포함해 제목과 키워드를 모두 프롬프트에 넣기 때문에, 오래 운영해도 같은 주제가 다시 나오지 않습니다. 모델이 놓칠 때를 대비해 키워드가 완전히 같은 항목은 코드에서 한 번 더 버립니다.

**추가된 주제는 `angle` 을 훑어보세요.** 제목과 키워드는 대체로 쓸 만하게 나오지만 각도가 뻔하면 글도 뻔해집니다. 마음에 안 드는 항목은 직접 고치거나 `status` 를 `skipped` 로 바꾸면 됩니다.

`취미와 반려생활` 은 소재가 마르지 않는 카테고리입니다. 시니어 취미와 반려 인구는 계속 늘고 검색어도 계절마다 갱신되니, 다른 카테고리가 얇아졌을 때 임시로 비중을 올려 버티는 완충재로 쓸 수 있습니다.

`어르신들의 이야기` 는 실제 취재라서 자동 보충 대상이 아닙니다. 확장기가 건너뜁니다.

### 직접 추가하기

`topic_queue.json` 의 `topics` 에 항목을 추가합니다.

```json
{
  "id": "A12",
  "category": "parent_time",
  "title": "검색될 만한 제목",
  "keyword": "부모님 무엇",
  "angle": "이 글이 다른 글과 다른 지점 한 문장",
  "status": "pending"
}
```

`angle` 이 제일 중요합니다. 비어 있으면 어디서나 볼 수 있는 뻔한 글이 나옵니다.

B2G 카테고리는 **도입 지자체가 생기면 그 자체가 최고의 콘텐츠**입니다. 담당 공무원은 기능 설명보다 "다른 지자체가 이미 쓰고 있다"를 찾습니다. 사례가 생기면 최우선으로 큐에 넣으세요.

## 11. 아직 안 한 것

- **자체 블로그(`dasibomlife.com/blog`)** — 장기적으로는 본 도메인에 콘텐츠가 쌓이는 게 유리합니다. 다만 지금 Firebase 호스팅은 `/**` 가 `index.html` 로 가는 SPA 구조라, `/blog` 경로를 쓰려면 `firebase.json` 의 rewrites 에 `/**` 보다 **위쪽에** 별도 규칙을 넣어야 합니다. 네이버 블로그가 자리를 잡은 뒤에 하는 게 순서입니다.
- **네이버 요약본 자동화** — 자체 블로그가 생기면, 네이버에는 요약본 + 원문 링크만 올리는 방식으로 바꿉니다. 지금은 네이버가 원문이라 해당 없습니다.
- **지표 수집** — 유입 키워드와 CTA 클릭률을 봐야 카테고리 비중을 재조정할 수 있습니다. 발행이 안정되면 붙입니다.
