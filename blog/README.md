# 다시봄라이프 블로그 운영

**시니어 정보 블로그**입니다. 네이버 블로그(blog.naver.com/dasibomlife)에 글을 쓰고 발행하는 파이프라인이 들어 있습니다.

---

## 1. 이 블로그의 원칙

**정보 블로그입니다. 다시봄라이프 홍보 블로그가 아닙니다.**

은퇴 이후 세대가 검색해서 찾아오면, 찾던 정보를 주고 끝냅니다. 읽고 나서 "쓸모 있었다"로 끝나면 그것으로 충분합니다.

- **본문에 다시봄라이프가 나오지 않습니다.** 글 생성기는 링크의 존재 자체를 모릅니다
- **글마다 다른 CTA 를 고민하지 않습니다.** 모든 글 끝에 똑같은 카드 하나가 붙습니다. 발행기가 붙입니다
- **사이드바에 배너 하나**를 답니다. 그게 전부입니다

```
─────────────

말하지 않으면 아무도 모릅니다.
오늘 건넨 한마디면 충분합니다.

이 블로그는 다시봄라이프가 씁니다.
은퇴 이후의 하루를 위한 서비스 — dasibomlife.com
```

**글 하나는 이렇게 끝납니다.** 정보로 시작해서 여운으로 닫고, 마지막에 누가 쓴 블로그인지만 밝힙니다. 홍보는 맨 아래 두 줄이 전부입니다.

카드는 세 층입니다 — `config.json` 의 `footer_card`.

| 층 | 무엇 | 글마다 다른가 |
|---|---|---|
| `divider` | 본문이 끝났다는 선 | 아니오 |
| `closing` | **카테고리별 감성 문구** | 카테고리에 따라 |
| `sign` | 운영 주체 서명 두 줄 | 아니오 |

감성 문구는 카테고리마다 하나씩 고정입니다. 그 카테고리를 읽고 나온 사람에게 건네는 한마디입니다.

| 카테고리 | 닫는 말 |
|---|---|
| 정책과 지원금 | 받을 수 있는 것을 챙기는 일은 염치의 문제가 아닙니다 / 오래 일해 오신 세월의 몫입니다 |
| 건강과 의료 | 몸이 보내는 신호를 알아듣는 것도 / 스스로를 아끼는 방법입니다 |
| 취미와 여가 | 무엇을 새로 시작하기에 늦은 나이라는 건 / 아마 없을 겁니다 |
| 요리와 살림 | 하루를 잘 건사하는 일이 / 결국 나를 잘 건사하는 일입니다 |
| 스마트폰과 디지털 | 몰라서 못 하는 것과 나이 들어 못 하는 것은 / 다른 이야기입니다 |
| 마음과 관계 | 말하지 않으면 아무도 모릅니다 / 오늘 건넨 한마디면 충분합니다 |
| 자서전과 기록 | 잊히는 것과 남기는 것 사이에 / 오늘 적어 둔 한 줄이 있습니다 |

**감성 문구에 서비스 이야기를 넣지 마세요.** 여기가 광고가 되는 순간 독자가 앞의 정보까지 의심합니다. 홍보는 서명 두 줄로 충분합니다.

`enabled: false` 로 두면 카드 전체가 빠집니다.

### 해마다 확인하라는 안내는 네 카테고리에만

기준·절차가 바뀌는 글에만 붙입니다 — 정책·건강·살림·디지털(`writing.notice_categories`).

취미·마음·자서전은 뺐습니다. 감성으로 닫는 글 끝에 "공단에 확인하세요" 가 붙으면 여운이 깨집니다. 특정 글만 빼려면 원고에 `skip_notice: true` 를 넣습니다.

### 해시태그는 세 층

| 층 | 예 | 하는 일 |
|---|---|---|
| 글 고유 키워드 | `#기초연금수급자격` `#소득인정액` | 검색 유입 |
| **카테고리 고정 태그** | `#노후정책` | **관련글을 서로 잇습니다** |
| 블로그 공통 | `#시니어` `#노후생활` | 블로그 전체 묶음 |

네이버는 태그를 누르면 **그 블로그의 같은 태그 글 목록**으로 갑니다. 카테고리 태그 하나가 그 카테고리 글끼리 서로를 이어 주는 통로입니다. 한 편을 읽고 나간 사람이 다음 글로 넘어가는 자리라, 이게 없으면 글이 각자 떠 있습니다.

`categories[].tag` 에 있습니다 — 노후정책 / 시니어건강 / 노후취미 / 살림정보 / 스마트폰사용법 / 노후마음 / 인생기록.

**한번 정하면 바꾸지 마세요.** 바꾸면 이전 글들과 묶음이 끊깁니다.

합쳐서 8~9개가 붙습니다(검수 기준은 5~12개).

**왜 이렇게 하나.** 글 내용에 맞춰 링크를 고르기 시작하면 글이 그 링크를 향해 휘어집니다. 국민연금 글 끝에 일자리 링크를 붙이는 식이 됩니다. 그러면 독자가 광고로 읽고, 네이버는 상업성 블로그로 판정합니다. 저품질을 맞으면 검색 노출 자체가 사라집니다.

## 2. 카테고리와 목차 템플릿

| 카테고리 | 비중 | 편수 | 성격 |
|---|---|---|---|
| **정책과 지원금** | 20% | 25 | 매년 반복 검색되는 에버그린. 목차 고정이 가장 잘 먹는 곳 |
| **건강과 의료** | 20% | 35 | 광고 단가가 높은 영역. 질환 + 영양소 |
| **취미와 여가** | 18% | 45 | 트로트 팬덤·파크골프. 트래픽이 가장 크게 움직임 |
| **요리와 살림** | 14% | 15 | 단톡방 공유 최강. 소재가 안 마름 |
| **스마트폰과 디지털** | 14% | 12 | 카톡으로 그대로 퍼짐 |
| **마음과 관계** | 8% | 14 | 검색은 적지만 댓글이 붙고 다시 찾아옴 |
| **자서전과 기록** | 6% | 15 | 유일하게 서비스와 이어지는 축 |

**162편, 약 54주치**입니다.

### 목차를 고정한 이유

카테고리마다 **글의 뼈대를 정해두고 매번 프롬프트에 넣습니다.** `config.json` 의 `categories[].template` 입니다.

목차가 고정되면 세 가지가 해결됩니다. 글마다 구성을 새로 고민하지 않아도 되고, 자동 생성이라도 품질이 일정하게 나오고, **소재가 떨어지지 않습니다** — 식재료 이름 하나만 바꿔 넣으면 같은 뼈대로 새 글이 나옵니다.

### 정책과 지원금 · 20%

기초연금·국민연금·교통카드·경로우대·의료 혜택·세금 감면·에너지바우처·장기요양

```
1. 서론 — 이 제도를 왜 지금 알아야 하는지. 몰라서 못 받는 사람이 있다는 점을 짚기
2. 지원 대상 — 나이 / 소득 / 재산 으로 갈래를 나눠 정리. '나는 되나' 를 바로 판단할 수 있게
3. 지원 내용 — 무엇을 받는지. 액수 대신 무엇에 따라 갈리는지(단독·부부, 감액 조건)와 확인처
4. 신청 방법 — 어디서, 언제, 온라인과 방문 중 어느 쪽이 되는지. 순서대로
5. 필요 서류 — 체크리스트처럼 한 줄에 하나씩
6. 결론 — 자주 묻는 질문 하나에 답하고, 세 줄로 요약
```

### 건강과 의료 · 20%

관절·치아·치매·눈·수면 등 질환별 정보 · 영양소별 설명 · 집에서 하는 스트레칭

```
1. 서론 — 이 문제로 겪는 흔한 고충에 공감. 혼자만 그런 게 아니라는 점
2. 원인과 초기 신호 — 스스로 확인할 수 있게 체크리스트로. '이 중 두 가지 이상이면' 같은 기준
3. 핵심 정보 — 보험 적용 기준, 치료 방법, 영양소가 하는 일 등 주제에 맞는 본론
4. 집에서 할 수 있는 것 — 생활 습관과 도움이 되는 음식
5. 병원에 가야 할 때 — 미루면 안 되는 기준을 구체적으로. 이 항목은 반드시 넣기
6. 결론 — 정기 검진의 중요성을 한 번 짚고 따뜻하게 닫기
```

### 취미와 여가 · 18%

트로트 팬덤(팬카페·문자투표·티켓 예매)·파크골프·게이트볼·당구·서예·등산·텃밭·반려동물·당일치기 여행

```
1. 서론 — 왜 지금 이걸 찾아보게 되는지에 공감. 시작을 망설이는 마음
2. 무엇을 하는 것인지 — 처음 듣는 사람도 알 수 있게
3. 시작에 필요한 것 — 준비물, 장소, 등록 절차. 장비는 고르는 기준만(상표 금지)
4. 처음 겪는 걸림돌 — 첫날 실제로 무엇이 어려운지
5. 이어 가는 법 — 얼마나 자주, 누구와
6. 결론 — 자주 묻는 질문 하나에 답하고 짧게 닫기
```

### 요리와 살림 · 14%

혈당·혈압 식단·밑반찬·식재료 효능·수건 냄새·세탁기 청소·곰팡이·배수구·냉장고 정리

```
1. 서론 — 이 문제로 겪는 불편에 공감. 흔한 일이라는 점
2. 왜 생기는지 — 두세 문장으로
3. 준비물 — 집에 있는 것 위주. 없으면 대안도 함께
4. 순서 — 한 번에 하나씩. '적당히' 대신 눈으로 확인하는 기준
5. 주의할 점 — 섞으면 위험한 것, 하면 안 되는 것
6. 결론 — 다시 안 생기게 하는 주기와 습관으로 닫기
```

### 스마트폰과 디지털 · 14%

카카오톡·유튜브 설정·스미싱과 사기 예방·키오스크·앱 사용법·간편결제·저장공간

```
1. 서론 — 글씨가 작아 답답했던 경험에 공감. 나이 탓이 아니라 설정 탓이라는 점
2. 시작 전 확인 — 기종이나 앱 버전에 따라 달라질 수 있는 부분
3. 1단계 — 어느 화면에서 무엇을 누르는지. 화면에 적힌 말을 그대로 인용
4. 2단계 — 세부 조작. 한 번에 한 동작씩
5. 3단계 — 제대로 바뀌었는지 확인하는 법
6. 안 될 때와 마무리 — 흔히 막히는 두세 가지를 짚고, 이제 편하게 쓰시라고 격려하며 닫기
```

### 마음과 관계 · 8%

은퇴 후 부부 대화·자녀와의 거리·손주·친구 만들기·상실·외로움·독립적인 노후

```
1. 이런 순간 — 겪는 장면 하나로 시작. 설명하지 말고 보여주기
2. 왜 그런가 — 진단하듯 규정하지 말고 해석으로
3. 흔히 하는 대응과 그 한계
4. 다르게 해 볼 것 — 오늘 할 수 있는 하나
5. 닫는 문장 — 짧게. 위로만 하고 끝내지 않기
```

### 자서전과 기록 · 6%

자서전·회고록·사진 정리·유언장·사전연명의료의향서·손주에게 남기는 글

```
1. 그 전제 확인 — 어떤 생각에 막혀 있는지
2. 어디서 막히는가 — 혼자 할 때 실제로 벌어지는 일
3. 왜 막히는가 — 의지나 재주의 문제가 아님을 짚기
4. 크기를 줄이는 법 — 오늘 할 수 있는 한 가지
5. 닫기 — 필요하면 다른 방법을 한 번만 언급. 어색하면 넣지 않음
```

### 목차를 빌려 쓰는 경우

주제에 `template` 을 지정하면 그 카테고리 목차를 대신 씁니다.

```json
{ "id": "P21", "category": "hobby", "template": "digital" }
```

팬카페 가입, 문자투표, 티켓 예매는 **취미지만 성격은 단계형**입니다. 순서를 하나씩 짚어야 하는 글이라 디지털 목차를 빌려 씁니다. 큐에 5편이 그렇게 지정되어 있습니다.

검수기가 소제목 개수를 세서 목차 단수에 크게 못 미치면 경고합니다.

### 트래픽이 실제로 어디서 오는가

| 주제 | 왜 |
|---|---|
| **팬카페 가입·문자투표·티켓 예매** | 자녀 도움 없이 혼자 하고 싶어 매일 검색합니다 |
| **파크골프** | 빠르게 퍼지는 운동이고 장비 검색이 따라붙습니다 |
| **임플란트·잇몸·백내장** | 광고 단가가 높은 영역입니다 |
| **수건 냄새·세탁기 거름망** | 단톡방으로 가장 많이 퍼집니다 |
| **은퇴 후 부부·자녀와의 거리** | 검색은 적지만 댓글이 붙고 다시 찾아옵니다 |

### 지켜야 할 선

- 취미와 여가 — **특정 가수를 응원하거나 편들지 않습니다.** 방법만 씁니다. 투표·예매는 회차마다 바뀌므로 뼈대만 쓰고 방송사 공지 확인으로 닫습니다. 장비는 고르는 기준만, 상표는 쓰지 않습니다
- 건강과 의료 — 낫는다고 쓰지 않습니다. **마지막 "병원에 가야 할 때" 항목이 글의 안전장치**라 반드시 넣습니다
- 요리와 살림 — 혈당·혈압에 "좋다", "낮춰 준다" 고 단정하지 않습니다. 무엇이 덜 올리는지로 씁니다. **세제를 섞을 때 위험한 조합은 반드시 경고**를 넣습니다
- 마음과 관계 — 감정을 진단하듯 규정하지 않습니다. 위로만 하고 끝내지 않고 오늘 해볼 것 하나를 남깁니다

### 자서전과 기록만 서비스를 언급할 수 있습니다

`categories[].allow_brand` 로 지정합니다. **이 카테고리 하나만** 본문에서 다시봄라이프를 말할 수 있고, 그때도 **글 전체에서 한 번**입니다.

여섯 카테고리가 트래픽 축이라면 이곳은 서비스와 이어지는 축이라 성격이 다릅니다. 광고를 정보 사이에 골고루 뿌리면 독자가 어느 글도 못 믿습니다. 한 곳에 모아두면 독자가 알고 들어오고, 나머지 글의 신뢰가 지켜집니다.

**"쓰는 법" 을 단계별로 알려주지 않습니다.** 그러면 블로그가 서비스를 대체합니다. "왜 대부분 시작만 하고 멈추는가" 를 다룹니다.

```bash
npm run cats     # 카테고리별 목차와 주제 목록
```

## 3. 문체와 사실 규칙

### 독자를 대하는 법

읽는 사람은 **시니어 본인**입니다. 자녀에게 설명하듯 쓰면 읽는 사람이 대상화됩니다.

- 독자에게 **직접** 말합니다. `어르신은`, `부모님께` 같은 3인칭 금지
- `~해드리세요`, `챙겨드리세요` 같은 돌봄 대상 취급 금지
- 외래어·줄임말 금지. 꼭 쓰면 우리말 풀이를 붙일 것
- 나이를 이유로 못 한다가 아니라, 방법을 바꾸는 이야기로
- 어떤 서비스나 앱도 권하지 않음

### 시간이 지나도 틀리지 않게

`config.json` 의 `writing.volatility_rules` 에 있습니다.

| 써도 되는 것 | 쓰면 안 되는 것 |
|---|---|
| 나이 기준 (만 65세 등) | 금액·요율·지원금 액수 |
| 자격 요건의 갈래 | 수익률·연금 수령액 |
| 계산하는 방법 | 지어낸 통계·비율·순위 |
| 확인처 (주민센터·공단·복지로) | 상대적 시간 표현 (올해·작년·요즘) |

**나이와 자격 요건은 적어도 됩니다.** 잘 바뀌지 않고, 이게 없으면 정책 글이 쓸모없어집니다. 반면 금액은 해마다 바뀌므로 "주민센터에서 확인" 으로 넘깁니다.

### 검수기가 막습니다

프롬프트로 넣는 것만으로는 부족합니다. `lint_post.mjs` 가 발행 직전에 검사하고, **차단 항목이 하나라도 있으면 발행을 멈춥니다.**

```bash
npm run lint                            # out/ 의 모든 원고
node lint_post.mjs --post out/B01_x.json
```

| 차단 (발행 중단) | 확인 권장 |
|---|---|
| **본문에 서비스 이름** (자서전 카테고리 제외) | 제목 32자 초과 |
| **브랜드 3회 이상 반복** (자서전 카테고리) | |
| **다른 데로 넘기려는 마무리** | 제목에 검색 키워드 없음 |
| 독자를 3인칭으로 부름 | 태그 개수 (5~12개 밖) |
| 돌봄 대상 취급 | 나이를 한계로 서술 |
| 금액·가격 / 연금·요율 수치 | 제품·병원 추천 가능성 |
| 금융상품 추천·판단 | 분량 범위 밖 |
| 상대적 시간 표현 | |
| 출처 없는 통계·비율 / 순위 | |
| 단정 표현 (최고·유일·100%) | |
| 의학적 단정 | |
| 마크다운 기호 잔존 / 본문 속 링크 | |
| 분량 목표의 80% 미만 / 제목 이모지 | |

통계는 **같은 문장에 출처가 있으면 통과**시킵니다. "조사에 따르면 68%" 는 지나가고, 근거 없는 "100%" 만 걸립니다.

규칙이 과하면 `lint_post.mjs` 의 `RULES` 를 조정하거나 `--skip-lint` 로 넘길 수 있습니다. 다만 **넘기기 전에 왜 걸렸는지는 꼭 보세요.**

## 6. 글마다 이미지 여섯 장

**글에 이미지가 없으면 아무도 끝까지 읽지 않습니다.** 체류시간이 안 나오면 네이버가 노출을 밀어냅니다. 그래서 발행 전 검수에서 이미지 수를 셉니다 — `config.json` 의 `writing.min_images` 아래면 발행이 막힙니다.

글 한 편에 들어가는 것:

| | 무엇 | 만드는 것 |
|---|---|---|
| 1장 | 대표 이미지 (제목 썸네일) | `gen_image.mjs` |
| 3장 | 본문 일러스트 | `gen_illust.mjs` — Gemini |
| 2장 | 본문 정보 카드 | `gen_figures.mjs` — 직접 그림 |

### 위치는 원고가 정합니다

원고 JSON 의 `illustrations[].after` 와 `figures[].after` 에 **본문에 실제로 있는 줄**을 그대로 적습니다. 발행기가 그 줄을 친 직후에 이미지를 넣습니다. 본문에 없는 줄이면 조용히 빠지니, 검수기가 미리 막습니다(`image-misplaced`).

소제목 줄을 쓰는 것이 가장 안전합니다.

### 일러스트 — Gemini

키는 **`그때그시절` 이미지 생성기와 같은 파일**을 씁니다 — 저장소 루트의 `tools/gemini.key`. 이미 쓰고 계시면 새로 발급받으실 필요 없습니다. (`.gitignore` 에 있어 커밋되지 않습니다. 환경변수 `GEMINI_API_KEY` 도 됩니다.)

```bash
node gen_illust.mjs --all --limit 3    # 먼저 3장만 뽑아 화풍 확인
npm run illust                         # out/ 의 모든 원고
node gen_illust.mjs --post out/B01_xxx.json
node gen_illust.mjs --post out/B01_xxx.json --force   # 이미 있어도 다시
```

**처음에는 `--limit 3` 으로 세 장만 뽑아 보세요.** 화풍이 마음에 안 드는 채로 89장을 다 뽑으면 다시 뽑느라 한도를 두 배로 씁니다.

이미 만든 그림은 건너뜁니다. **중간에 끊겨도 같은 명령으로 이어 돌리면 됩니다.** 무료 키 한도(429)에 걸리면 헛돌지 않고 거기서 멈추니, 다음 날 같은 명령을 주시면 됩니다. 그림이 마음에 안 들면 원고의 `prompt` 를 고치고 `--force` 로 다시 뽑으세요.

**사진을 안 쓰는 이유.** 남의 사진을 자동으로 가져다 쓰면 저작권과 초상권이 걸립니다. 자동 발행이라 한 장씩 사람이 걸러낼 수 없으니 애초에 만들어 씁니다. 화풍은 `config.json` 의 `illustration.style` 에 고정해 두었고, **일본풍이 섞이지 않도록 막는 문구**도 함께 넣었습니다 — `tools/gen_nostalgia.mjs` 에서 겪은 문제라 같은 방어를 씁니다. **이걸 바꾸면 그때부터 나오는 그림이 이전 글들과 따로 놉니다.** 바꾸려면 전체를 `--force` 로 다시 뽑을 각오를 하고 바꾸세요.

키가 없어도 발행은 됩니다. 카드 이미지만 들어갑니다.

### 정보 카드 — 다섯 가지

```bash
npm run figures
node gen_figures.mjs --post out/B01_xxx.json
```

| 종류 | 쓰는 곳 |
|---|---|
| `checklist` | 준비물, 서류, 증상 확인 — 한 줄에 하나 |
| `steps` | 순서가 있는 것 |
| `compare` | 되는 것 / 안 되는 것 |
| `note` | 하면 안 되는 것 — **이 카드만 붉은색** |
| `summary` | 세 줄 요약 — 로고가 들어가는 유일한 카드 |

카드는 본문에 이미 있는 내용을 옮긴 것이어야 합니다. 카드에만 있는 정보를 만들지 마세요. 이미지를 못 보는 사람에게 글이 반쪽이 됩니다.

## 7. 매일 쓰는 명령

```bash
npm run status      # 큐 현황 (카테고리별 남은 편수, 몇 주치인지)

npm run figures     # 본문 정보 카드 다시 만들기
npm run illust      # 본문 일러스트 다시 만들기 (GEMINI_API_KEY 필요)
```

한 달에 한 번:

```bash
npm run stats       # 네이버 통계 → 우리 형식으로 (--csv 또는 --set)
npm run rebalance   # 읽힌 만큼 카테고리 비중 재조정 (12번 항목)
```

세부 옵션:

```bash
node run.mjs --count 3               # 3편 연속 (예약 슬롯이 차례로 밀림)
node run.mjs --id B01                # 특정 주제 지정

node run.mjs --headed                # 브라우저 보면서 (문제 생겼을 때)
```

**처음 2~3주는 `npm run draft` 로 원고를 눈으로 확인한 뒤 발행하시길 권합니다.**

### 발행 주기 — 격일 오전 9시

`config.json` 의 `schedule.interval_days: 2` 입니다. 요일을 고정하지 않고 **이틀에 한 번**씩 나갑니다.

```
1편 8/07(금) → 2편 8/09(일) → 3편 8/11(화) → … → 14편 9/02(수)
```

요일이 계속 밀리는 것이 오히려 낫습니다. 주말에만 읽는 사람과 평일에만 읽는 사람 양쪽에 번갈아 걸립니다.

**요일 방식으로 되돌리려면** `interval_days` 를 지우면 됩니다. 그러면 예전처럼 `publish_days` 를 씁니다.

### 예약을 미리 밀어 넣습니다

격일 발행이라고 이틀마다 컴퓨터를 켜 둘 필요는 없습니다. **네이버 예약 발행**에 한 번에 여러 편을 넣어 두면, 그 뒤로는 네이버가 알아서 내보냅니다.

```bash
node run.mjs --count 7
```

한 편 예약할 때마다 `topic_queue.json` 에 `reserved_for` 가 쌓이고, 다음 편은 **마지막 예약일 + 이틀**로 잡힙니다. 그래서 나눠서 여러 번 돌려도 날짜가 겹치지 않습니다.

```
오늘 7편 예약  → 8/07 · 8/09 · 8/11 · 8/13 · 8/15 · 8/17 · 8/19
2주 뒤 7편 더  → 8/21 · 8/23 · … (앞의 예약 뒤로 자동으로 이어짐)
```

예약을 물리거나 당기고 싶으면 `topic_queue.json` 의 해당 `reserved_for` 를 지우고 다시 돌리세요.

현재 큐는 161편이라 격일 기준 **약 46주치**입니다.

## 10. 발행이 깨졌을 때

네이버는 예고 없이 에디터 DOM 을 바꿉니다. 발행 실패는 대부분 이것입니다.

실패하면 **어느 단계에서 멈췄는지** 로그에 찍히고 `out/error_*.png` 스크린샷이 남습니다.

```bash
node publish_naver.mjs --post out/B01_xxx.json --headed --pause   # 셀렉터 확인
node publish_naver.mjs --post out/B01_xxx.json --dry-run --headed # 발행 없이 화면만
```

Playwright Inspector 의 Explore 로 바뀐 셀렉터를 찍어서 `lib/selectors.mjs` 의 해당 항목 **맨 앞에** 추가하세요. 기존 값은 지우지 마세요 — 네이버가 되돌릴 때가 있습니다.

## 11. 큐가 마르지 않게

`npm run status` 가 카테고리별로 몇 주치 남았는지 보여줍니다. 8주 미만이면 `주의`, 4주 미만이면 `보충 필요`.

```bash
npm run expand                                      # 8주 미만인 카테고리를 알아서 채움
node expand_queue.mjs --category money --count 15
node expand_queue.mjs --auto --threshold 12         # 임계값을 올려 미리 채움
```

**중복은 큐 전체 기준으로 걸립니다.** 발행이 끝난 글까지 포함해 제목과 키워드를 프롬프트에 넣기 때문에, 오래 운영해도 같은 주제가 다시 나오지 않습니다.

**추가된 주제는 `angle` 을 훑어보세요.** 각도가 뻔하면 글도 뻔해집니다.

## 12. 한 달 뒤 비중 재조정

**한 달(격일 14편) 발행한 뒤, 실제로 읽힌 카테고리를 늘립니다.**

```bash
npm run stats -- --csv ~/Downloads/블로그통계.csv    # 네이버 통계 → 우리 형식으로
npm run rebalance                                    # 제안만 봅니다
npm run rebalance -- --apply                         # 비중을 실제로 바꿉니다
```

통계 화면에 내려받기가 없으면 숫자만 불러 주셔도 됩니다.

```bash
npm run stats -- --set "B01=1240,P26=4210,H01=2100"
```

### 총 조회수로 판단하지 않습니다

비중이 큰 카테고리는 글이 많으니 총 조회수도 당연히 큽니다. 그대로 비교하면 **"많이 썼으니 많이 읽혔다" 를 "인기 있다" 로 착각**합니다.

그래서 **편당 평균 조회수**로 봅니다. 적게 쓴 카테고리도 공평하게 평가됩니다.

```
지수 = 그 카테고리 편당 조회수 ÷ 전체 편당 평균
지수 1.63 → 평균보다 63% 더 읽힘 → 비중을 올림
```

### 조금씩만 움직입니다

한 달이면 카테고리당 한두 편입니다. **그 한 편이 우연히 터지거나 묻힐 수 있습니다.** 표본이 이만큼 작을 때 비중을 크게 흔들면 다음 달에 반대로 흔들게 됩니다.

| 안전장치 | 값 | 왜 |
|---|---|---|
| 한 번에 움직이는 폭 | ±35% | 우연을 실력으로 착각하지 않기 위해 |
| 최소 비중 | 5% | **어떤 카테고리도 없애지 않습니다** |
| 조정 시작선 | 10편 | 그 아래면 조정하지 않고 그대로 둡니다 |
| 표본 부족 기준 | 2편 미만 | 그 카테고리는 아예 건드리지 않습니다 |

**마음과 관계·자서전과 기록은 조회수가 낮게 나올 것입니다.** 검색량 자체가 적은 주제라 당연합니다. 그런데 이 두 축이 이 블로그의 색이고, 댓글이 붙고 다시 찾아오는 곳입니다. 최소 5% 바닥이 그래서 있습니다 — **조회수만 보면 이 블로그는 정보만 남고 온기가 사라집니다.**

### 숫자가 알려주지 않는 것

지수가 높게 나왔다고 그 주제가 좋았던 것은 아닙니다. **제목이 좋았을 수도, 그날 검색이 몰렸을 수도** 있습니다.

비중을 바꾸기 전에 잘된 글을 직접 열어 보세요. 제목인지, 주제인지, 첫 문단인지 — 그걸 봐야 다음 글에 옮길 수 있습니다. 비중만 바꾸면 같은 카테고리의 안 되는 글이 늘어날 뿐입니다.

바꾼 이력은 `config.json` 의 `_weight_history` 에 남습니다.

## 13. 아직 안 한 것

- **애드포스트** — 글이 쌓이고 유입이 잡힌 뒤에 판단할 문제입니다.
- **네이버 서치어드바이저** — 유입 키워드를 봐야 카테고리 비중을 재조정할 수 있습니다. 글이 20~30편 쌓인 뒤에 등록하세요.

## 14. 노트북 없이 이미지 만들기 (GitHub Actions)

명령창을 열지 않고 브라우저에서 버튼 하나로 이미지를 만들 수 있습니다.

### 최초 1회 — 키 등록

저장소 → **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 값 |
|---|---|
| `GEMINI_API_KEY` | 노트북의 `tools/gemini.key` 안에 있는 키 한 줄 |

한 번 넣으면 끝입니다. 이 값은 GitHub 안에서 암호화되어 저장되고, 실행 기록에도 찍히지 않습니다.

### 돌리기

저장소 → **Actions → 블로그 이미지 생성 → Run workflow**

| 입력 | 뜻 |
|---|---|
| `limit` | 이번에 뽑을 일러스트 장수. **처음에는 `3`** 으로 두고 화풍부터 확인하세요. `0` 이면 남은 것 전부 |
| `post` | 특정 원고만 (예: `B01`). 비우면 전체 |
| `force` | 이미 있는 그림도 다시 뽑기. **화풍을 바꾼 뒤에만** 켜세요 |

대표 이미지와 정보 카드는 호출 비용이 없어서 매번 전체를 다시 뽑습니다. **비용이 드는 것은 일러스트뿐이고, 이미 만든 그림은 건너뜁니다.**

### 결과 보기

- 실행이 끝나면 **Summary** 에 장수가 표시됩니다
- **Artifacts** 에서 그림을 통째로 내려받아 볼 수 있습니다 (14일 보관)
- 저장소에도 자동으로 커밋되니, 노트북에서 `git pull` 하시면 내려옵니다

### 자동으로 돌지 않습니다

`workflow_dispatch` 만 걸어 두었습니다. **사람이 버튼을 눌러야만 돕니다.** 이미지 생성에는 호출 비용이 들기 때문에 밀어놓기(push)나 시간표로 도는 일이 없어야 합니다.
